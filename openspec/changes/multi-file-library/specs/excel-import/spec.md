## MODIFIED Requirements

### Requirement: Excel 文件选取与导入
系统 SHALL 在文件库页提供「Excel 导入」按钮，点击后通过原生文件选择组件（ACTION_OPEN_DOCUMENT 等价机制）唤起系统文件选择器；选择器 MUST 以 Excel 文件类型过滤（.xlsx / .xls 及对应 MIME），使列表仅显示 Excel 文件。用户选取文件后系统解析并导入到文件库（多文件模型），并自动进入该文件的工作簿页。

#### Scenario: 选取 xlsx 文件导入成功
- **WHEN** 用户在文件库页点击「Excel 导入」，系统选择器（仅显示 Excel 文件）中选取一个结构合法的 `.xlsx` 文件
- **THEN** 系统解析该文件入库，导入完成后展示成功反馈（含工作表数量），并自动进入该文件的工作簿页、选中第一个工作表

#### Scenario: 选取 xls 文件导入成功
- **WHEN** 用户选取一个结构合法的 `.xls`（Excel 97-2004 二进制格式）文件
- **THEN** 系统与 `.xlsx` 同等解析并导入成功

#### Scenario: 类型过滤在系统选择器生效
- **WHEN** 系统文件选择器打开时手机上存在截图、PDF、Word 等非 Excel 文件
- **THEN** 选择器列表仅显示 Excel 文件（厂商 UI 差异导致的显示范围以外，本约束不弱于系统默认过滤能力）

#### Scenario: 取消选取
- **WHEN** 用户在文件选择器中取消操作
- **THEN** 系统不发生任何状态变化，文件库列表保持不变

### Requirement: 解析结果持久化
系统 SHALL 将文件库中每个文件的解析结果、每文件所选工作表持久化到本地存储（多文件记录，按文件标识索引）；App 重启后 SHALL 在文件库页自动恢复全部文件。系统 MUST NOT 监听原文件变化；同名文件重新导入时 SHALL 覆盖旧记录（导入时间更新）。

#### Scenario: 重启恢复
- **WHEN** 用户导入多个文件后完全关闭并重新打开 App
- **THEN** 文件库列表完整恢复（含每个文件的解析数据与各自上次选中的工作表）

#### Scenario: 重新导入覆盖
- **WHEN** 用户在 Excel 修改数据后再次导入选取与库中同名的文件
- **THEN** 该文件的记录被新内容完全覆盖，列表位置保持、导入日期更新；库内其他文件不受影响

#### Scenario: 旧版单文件数据迁移
- **WHEN** App 从旧版本（单工作簿模型）升级且本地存在旧导入数据
- **THEN** 旧数据自动迁移为文件库中的一条记录，用户无感、无需重新导入

### Requirement: 导入状态与进度反馈
系统 SHALL 在解析期间展示进行中状态并阻止重复导入操作；解析 MUST 在后台异步执行，界面不得冻结。

#### Scenario: 大文件解析进度
- **WHEN** 用户导入一个包含数万行数据的工作簿
- **THEN** 界面显示解析进行中的加载反馈，期间可正常取消或等待，导入按钮不可重复触发

#### Scenario: 文件损坏或不可读
- **WHEN** 选取的文件不是合法的 Excel 文件（如改名的文本文件）或已损坏
- **THEN** 系统展示导入失败提示（不崩溃），文件库已有文件不受影响

## REMOVED Requirements

### Requirement: 清空导入数据
**Reason**: 单工作簿时代的全局清空语义被文件库能力取代：逐文件删除由 `file-library` 能力的「逐文件删除」承接，全量清空由 `file-library` 能力的「全局清空」承接（入口移至文件库页，文案语义更新），避免同一语义在两个能力中重复定义。
**Migration**: 旧版清空按钮（工作簿顶栏）移除；用户在文件库页使用逐项删除或全局清空。规格引用见 `file-library` spec。
